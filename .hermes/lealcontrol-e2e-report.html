Hallazgos y soluciones propuestas

F-001 · Alta La API no arranca contra la base de desarrollo actual

Área: Base de datos / Migraciones

Evidencia: dotnet run contra lealcontrol falló con PostgreSQL 42701: column "CustomFields" of relation "opportunities" already exists. Stack: Program.cs:92 crm.Database.MigrateAsync().

Impacto: Bloquea el arranque local normal. Para poder seguir las pruebas usé una base limpia no destructiva lealcontrol_e2e_hermes.

Solución propuesta: Reconciliar migraciones EF con cambios manuales: crear una migración idempotente o marcar la migración aplicada solo si el esquema coincide; evitar mezclar EnsureCrmTablesAsync con EF migrations para las mismas columnas. Agregar prueba de arranque contra una base con datos/migraciones previas.

F-002 · Alta Hay una clave Gemini hardcodeada en appsettings.json

Área: Seguridad / Configuración

Evidencia: src/Host/LealControl.Api/appsettings.json línea 18 contiene Gemini:ApiKey con valor real.

Impacto: Secreto expuesto en repositorio/GitHub y en builds; riesgo de abuso de cuota y fuga de credenciales.

Solución propuesta: Rotar/revocar esa clave, eliminarla del repo, moverla a variables de entorno/User Secrets: Gemini__ApiKey. Añadir appsettings.json saneado y un secret-scanner en CI.

F-003 · Alta Crear categoría de producto devuelve 500

Área: Ventas / Catálogo

Evidencia: POST /api/v1/sales/categories devolvió NullReferenceException en ProductUseCases.cs:296 porque request.Model es null.

Impacto: La administración de categorías desde UI/API queda rota; el catálogo pierde clasificación y defaults contables/impositivos.

Solución propuesta: Cambiar endpoint para recibir ProductCategoryWriteModel y construir CreateCategoryCommand(model), o ajustar frontend para enviar { model: ... }. Recomiendo endpoint consistente con products/quotes: sales.MapPost("/categories", async (ProductCategoryWriteModel body, ISender sender, ...) => sender.Send(new CreateCategoryCommand(body))). Agregar integration test para POST /categories.

F-004 · Alta La pantalla Proveedores muestra 0 aunque existen proveedores

Área: CRM / Proveedores UI

Evidencia: GET /api/v1/crm/suppliers devuelve proveedores, pero /proveedores muestra "TOTAL PROVEEDORES 0". SuppliersPage.tsx usa api.listCustomers(term) con role default "customer" y luego filtra isSupplier.

Impacto: El usuario cree que no hay proveedores; no puede gestionar proveedores ya cargados por endpoint dedicado ni ver los importados correctamente.

Solución propuesta: En SuppliersPage llamar api.listCustomers(term, "supplier") o api.listSuppliers(term). Unificar modelo: si proveedores son Customers con isSupplier, no duplicar endpoint; si son entidad Supplier dedicada, la UI debe usar ese endpoint. Agregar test UI/API para /proveedores con fixtures.

F-005 · Media Cliente frontend contiene endpoints CRM inexistentes

Área: CRM Frontend API

Evidencia: Swagger expone /opportunities/{id}/move y /classify. frontend/src/api/client.ts también define moveStage→/stage, markWon→/win y markLost→/loss-reason; los probes devolvieron 404 esperado.

Impacto: Botones o componentes que usen esos helpers fallarán silenciosamente o con error al intentar ganar/perder/mover oportunidades.

Solución propuesta: Eliminar helpers obsoletos o redirigirlos a moveOpportunity(id,"Won") / moveOpportunity(id,"Lost", reason). Agregar verificación estática que compare rutas del cliente contra swagger.

F-006 · Media Campos enum aceptan solo nombres técnicos y devuelven errores JSON extensos

Área: CRM / Validación y UX API

Evidencia: role="Compras" en contacto y jurisdiction="CABA" en alícuotas fiscales devolvieron 400 de deserialización. Con role=Commercial y jurisdiction=Agip pasaron.

Impacto: Si una importación/cliente externo envía etiquetas de negocio en español, falla antes de llegar a validadores de dominio; el error no es amigable.

Solución propuesta: Agregar DTOs con strings y mapeadores tolerantes a aliases (Compras→Commercial, CABA→Agip), o asegurar selects cerrados en frontend e importaciones. Configurar ProblemDetails para no exponer stack traces en Development compartido.

F-007 · Media npm audit reporta 5 vulnerabilidades: 2 high, 3 moderate

Área: Frontend / Dependencias

Evidencia: npm audit --json: xlsx high sin fix automático; vite/esbuild high/moderate; react-router-dom moderate.

Impacto: Riesgo en importación Excel y dev server; xlsx tiene prototype pollution y ReDoS reportados.

Solución propuesta: Evaluar reemplazar xlsx por una versión comercial de SheetJS o librería alternativa mantenida; subir Vite a versión segura compatible; actualizar react-router-dom a versión corregida. Ejecutar build/regresión luego.

F-008 · Baja Bundle principal muy grande

Área: Frontend / Performance

Evidencia: npm run build: index JS 2,494 KB minificado, 689 KB gzip; Vite advierte chunks > 500 KB.

Impacto: Carga inicial más lenta y peor experiencia en conexiones lentas.

Solución propuesta: Separar módulos con React.lazy/dynamic import por rutas, manualChunks para vendor, y cargar xlsx/html2pdf solo en pantallas que lo usan.

F-009 · Baja Warnings de ValueComparer en colecciones convertidas a JSON

Área: EF Core / Persistencia

Evidencia: dotnet test y dotnet run advierten CustomerEquipment.CustomAttributes, Opportunity.CustomFields y Product.CustomAttributes sin ValueComparer.

Impacto: EF puede no detectar cambios internos en diccionarios/listas, generando actualizaciones perdidas o tracking inconsistente.

Solución propuesta: Agregar ValueComparer para esas propiedades o usar owned entities/json mapping con comparador estructural.
